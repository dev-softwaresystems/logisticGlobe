# Puerta de release propuesta

Responsable técnico CTO; coordinación PM; QA valida evidencia; PO valida funcionalidad; cliente decide aceptación externa.
Checklist: revisión de código independiente, comandos/evidencias, datos/migración no destructiva, rollback, SBOM/licencias, secretos/retención, TLS/proveedores, carga y recuperación según fase. Registrar revisión del código y digest exacto.
Estado: desarrollo local; sin aprobación de release externo, firma, CI remota o autorización de despliegue.
Acta: versión____, entorno____, evidencias____, riesgos aceptados____, condición de rollback____, decisión____, autoridad/fecha____. No prellenar aprobación.
